\section{工作经历}

\datedsubsection{\textbf{腾讯} | TEG 混元机器学习平台, 推理引擎工程师}{2025.06 - 2026.04}
\begin{itemize}
  \item \textbf{INT8 Blockwise W8A8 量化推理优化}（专利成果）\textbar{} 背景：LLM 推理中 INT8 量化是降低显存、提升吞吐的关键手段，但 Ampere 硬件上量化算子频繁执行数值转换严重影响性能。核心主导该方案从算法设计到端到端集成的全栈开发，代码量 $\sim$7200 行（CUDA 2200+，Triton/Python 3500+）。提出 Hybrid 二级 Scale 量化方案，将 FP32 scale 分解为 (Q\_int32, F\_fp32) 实现 K-Tile 维度连续 INT32 累加，消除 mainloop 中全部浮点指令；基于 CUTLASS 开发 3 种 CTA Tile 配置的 GEMM kernel 并实现 CTA Swizzle 优化 L2 缓存命中率；设计三级融合策略将激活在线量化的多步算子垂直融合为单 kernel。\textbf{Tensor Core 利用率从 48\% 提升至 65\%，算子时延降低 1.23x\textasciitilde 1.47x，Qwen3-8B 端到端 QPS 相比 BF16 提升 1.67x\textasciitilde 2.24x}。

  \item \textbf{Async N-gram GPU 投机解码}（PR \#29184 合入 vLLM 主线）\textbar{} 背景：vLLM 异步调度器通过重叠 CPU/GPU 提升吞吐，但 N-gram 投机解码依赖 CPU 逐 token 采样，每步需 CPU-GPU 同步成为瓶颈。作为项目 owner 将 N-gram Proposer 完全迁移至 GPU，利用 Torch 向量化操作将 CPU O(N) 查找优化为滑动窗口 O(1) 并行匹配；实现异步 D2H、Pinned Memory 复用、独立 CUDA Stream 等零同步设计，解除 CPU-GPU 同步阻塞。\textbf{H20 上 64\textasciitilde 512 并发吞吐提升 20\%\textasciitilde 39\%}。

  \item \textbf{DivPrune 视觉 Token 剪枝}\textbar{} 背景：多模态模型处理视频流时 encoder 阶段 vision token 过多导致显存与计算瓶颈。在 Qwen3-VL 中设计并实现基于最远点采样（Farthest-Point Sampling）的特征多样性剪枝方法，采用批量并行选取（parallel\_k=32）+ mRoPE 3D 位置编码附加方案，实现 EVS/DivPrune/关闭三种模式无缝切换，保持完全向后兼容。\textbf{Qwen3-VL 视频 Caption 等业务场景端到端吞吐提升 1.2x\textasciitilde 1.34x}。

  \item \textbf{Penalty-Aware Speculative Decoding}\textbar{} 背景：Speculative Decoding 中多 draft token 并行采样时，frequency/presence penalty 无法感知同批次更早位置的 token，导致计算错误。设计增量计数机制，在 Triton kernel 中以 BLOCK\_SIZE 粒度向量化匹配 vocab ID 并动态累加前置 draft token 出现次数；利用 tl.static\_range 编译期循环展开避免动态循环开销。\textbf{修正多 draft token 并行采样时的惩罚计算错误，保证生成约束正确性，性能开销可控}。
\end{itemize}
